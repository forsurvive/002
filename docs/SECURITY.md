## 2. 지금 있는 것

### 2-1. 개인판(로컬) 문지기 — 기준선 그대로

- 바인딩 `127.0.0.1`. Host 는 `127.0.0.1`·`localhost` 만 → DNS 재바인딩 차단.
- `POST /api` 는 `Content-Type: application/json` 만(text/plain 단순 요청 CSRF 차단, `415`).
- `Origin` 이 있으면 `http://(127.0.0.1|localhost):<같은 포트>` 만(`403`). Origin 없는 요청(폰 중계기)은 통과.
- 인증 없음 — 그 PC 를 쓰는 사람이 주인. `data/auth.json` 의 API 키는 **평문**이며 화면에는 `hasKey` 만 내려간다(개인판 한계, README 가 USB 주의를 이른다).

### 2-2. 1차 구현(호스팅 실행)에서 더한 것 — `tools/hosting.mjs`

로컬 기본값에서는 **아무것도 바뀌지 않는다**. `SE2_HOST` 를 루프백이 아닌 주소(예: `0.0.0.0`)로 줄 때만 켜진다.

- **허용 호스트**: 루프백 이름 + `SE2_ALLOWED_HOSTS` + 플랫폼이 알려 준 도메인(`REPLIT_DOMAINS`, `REPLIT_DEV_DOMAIN`). 그 밖의 Host 는 `403`(재바인딩 방어 유지).
- **Origin**: 허용 호스트로 온 요청은 같은 이름에서 온 Origin 만(https 는 앞단 프록시가 포트를 바꿀 수 있어 이름만, http 는 포트까지).
- **스테이징 출입 열쇠**(`SE2_ACCESS_KEY`, HTTP Basic): 루프백이 아닌 주소에 열 때 **없으면 서버가 뜨지 않는다**(fail-closed).
  16자 미만이면 거절. 비교는 SHA-256 다이제스트의 `timingSafeEqual`. 사용자 이름은 무시.
  열쇠 없이 굳이 열려면 `SE2_ALLOW_OPEN=1` 을 **명시**해야 한다(권장하지 않음).
- 열쇠 없이 들어올 수 있는 것은 둘뿐이고 둘 다 원고를 담지 않는다: `GET /healthz`(«ok»), 그리고 플랫폼 상태 검사를 위한
  `GET /` 의 작은 안내 페이지(브라우저의 주소창 이동이면 곧바로 로그인 창을 띄운다).
- **온라인판은 출입 열쇠를 쓰지 않는다(2026-10-05 사용자 결정 — «관리자든 학생이든 계정으로»).** 문은 앱 계정이 지킨다:
  로그인 실패 고삐 · 초대 코드 맞히기 고삐 · 세션 쿠키(HttpOnly) · 서버의 소유/역할 검사. `SE2_ACCESS_KEY` 가 비밀값에 남아 있어도
  온라인판은 무시하고, `SE2_ONLINE_GATE=1` 을 함께 적을 때만 아래 열쇠 화면이 선다.
  **처음 설정**(계정이 하나도 없을 때)은 바깥에 연 서버에서 «설정 코드»가 있어야 받는다 — 켤 때마다 새로 만든 12자(메모리에만),
  계정이 없을 때만 서버 콘솔에 찍힌다. 틀리면 IP 마다 15분에 5번까지. 콘솔을 볼 수 있는 사람(서버를 켠 사람)만 운영자가 된다.
- (선택) 온라인판의 출입 열쇠 화면 — 브라우저의 Basic 로그인 창 대신 **제 로그인 화면에서 열쇠를 받는다**(2026-10-04): 열쇠 전에는 어느 주소든 로그인 화면
  (`login.html` · `login.js` · `style.css` — 원고 없음)과 `POST /api/gate` 만 열린다. 맞는 열쇠 → `se_gate` 쿠키(HttpOnly · SameSite=Lax ·
  바깥이면 Secure · 30일, 값은 열쇠에서 뽑은 SHA-256 지문 — 열쇠 원문 아님). 틀린 열쇠는 IP 마다 15분에 5번까지. 화면 안의 요청은
  `401 code:'gate'` 만 받고 창을 띄우지 않는다. Basic 헤더도 그대로 받는다(도구 · 시험).
- 이것은 **사람 계정이 아니다.** 스테이징에서 기능을 보는 동안 낯선 접근을 막는 임시 울타리이고, Phase 3 의 계정·세션이 대신한다.
  실제 학생/기관 데이터를 스테이징 1차 구성에 넣지 않는다.

## 3. 인증(Phase 3 설계)

- **앱 자체 계정**(Replit 등 호스팅 계정과 독립 — 명세 AH-9). `AuthProvider` 경계를 두어 필요하면 Clerk/OIDC 로 바꿀 수 있게.
- 비밀번호: `crypto.scrypt`(Node 내장, 표준 KDF — 새 암호를 만들지 않는다). 매개변수는 OWASP 권장치 이상, 솔트 16바이트, 문자열에 매개변수 함께 저장 → 나중에 올릴 수 있다.
- 세션: 32바이트 난수 토큰을 쿠키(`HttpOnly; Secure; SameSite=Lax; Path=/`)에, DB 에는 **SHA-256 해시만**. 만료(예: 14일)·유휴 만료·로그아웃·비밀번호 변경 시 전부 폐기.
- 학생: 초대 코드(만들 때 한 번 보여 주고 해시만 저장, 만료·사용 횟수) → login_id + 비밀번호 설정. 이메일 강제 없음(명세 §34).
- 로그인 실패: 같은 문구(계정 존재 여부를 흘리지 않음) · IP+계정 기준 속도 제한 · 감사 로그.

## 5. Credential 저장

> 구현(2026-10-04): `ai/credentials.mjs` — 아래 설계대로 봉인 · AAD · key_version · 끝 4자리 표시 · 앞 키 끊기. 저장소는 지금 메모리 구현만 있고 PostgreSQL 구현은 Phase 3.

- **봉투 암호화**: AES-256-GCM, 행마다 12바이트 nonce, 인증 태그 저장. AAD = `owner_type|owner_id|provider|credential_id`(행 바꿔치기 방지).
- 마스터 키: 플랫폼 Secrets 의 `CREDENTIALS_KEY_V1`(32바이트, base64). 행에 `key_version` → 새 키로 다시 암호화(rotate) 가능.
- 복호화는 **worker 의 호출 직전**에만, 결과 문자열은 그 호출의 지역 변수로만. 웹 서버는 «저장·폐기·연결 테스트 요청»만 한다.
- 화면·API 응답: `{ provider, status, keyHint:'…a1b2', lastVerifiedAt }`. 원문은 다시 내려가지 않는다(명세 §16).
- 로그·오류·감사 로그에 키·`Authorization` 헤더·credential 객체 전체를 남기지 않는다 — 로거에 가리기 규칙(키 모양 정규식 + 이름 기반) + 시험.
- 플랫폼 공용 키(향후 managed AI)는 Secrets 의 환경 변수, 기관/개인 키는 **DB 에 암호화**(명세 AH-7 — 공용 환경 변수에 넣지 않는다).

## 6. 웹 보안 기본값(온라인)

- HTTPS 전용(플랫폼 TLS) · `Secure` 쿠키 · HSTS(사용자 도메인 연결 뒤).
- CSRF: `SameSite=Lax` + 상태 변경은 `POST /api`(JSON 전용) + Origin/Referer 검사(지금 문지기 확장).
- 헤더: `X-Content-Type-Options: nosniff` · `Referrer-Policy: same-origin` · CSP(인라인 스크립트 없음 — 지금 화면은 외부 파일만 쓴다) ·
  `frame-ancestors` 는 운영 도메인에서만 켠다(Replit 작업 공간 미리보기가 iframe 이므로 스테이징에서는 끔).
- 요청 본문 상한(예: 2MB, 자료 붙여 넣기는 파일 업로드 경로로) · 업로드 형식/크기 검사(txt·md 먼저, 명세 §63).
  → 구현(2026-10-05): 화면 `fileButton` 이 txt · md · 2MB · UTF-8 로 읽히는지 먼저 거르고, 서버(`tools/ops.mjs`)가 NUL 이 든 글(바이너리)을 자료 · 문서로 받지 않는다. 요청 본문은 5MB(작품 가져오기만 60MB · 로그인한 사람).
- 속도 제한: 로그인·초대 수락·작업 등록에 IP/계정 기준.
- 오류 응답에 내부 정보(스택·SQL·provider 원문) 금지. 다른 테넌트 id 는 «없음(404)».
- 감사 로그(명세 §61): 로그인/실패 · 권한 변경 · 기관 생성 · 라이선스 변경 · credential 변경 · 프로젝트 삭제 · 중요한 작품 삭제/복구.

### 6-1. 지금 온라인 서버(`online/server.mjs`)가 하는 것

- 로그인 전 `/api*` 401 · 프로젝트마다 소유 검사(아니면 404) · 상태 변경은 JSON + 같은 출처 Origin 만(아니면 403/415) · 낯선 Host 403 · 본문 5MB 상한(413).
- 머리줄: `nosniff` · `Referrer-Policy: same-origin` · CSP(`default-src 'self'`, 스크립트는 외부 파일만). `NODE_ENV=production` 일 때만 `X-Frame-Options: DENY` + `frame-ancestors 'none'`.
- 쿠키 `Secure` 는 바깥에 열 때(`SE2_HOST` 가 루프백이 아닐 때). 로그인 속도 제한의 주소는 기본이 소켓 주소이고, 플랫폼 앞단 뒤에서는 `SE_TRUST_PROXY=1` 로 `X-Forwarded-For` 의 마지막 값을 쓴다(앞단이 붙인 값 — 사람이 위조한 앞쪽 값은 보지 않는다).
- 500 응답에 까닭을 싣지 않는다(콘솔에는 오류 이름만).
- 감사 로그: 로그인/실패 · 비밀번호 변경 · 프로젝트 만들기/지우기 · 운영자 계정 발급 · 운영자 키 등록(`credential.set` — 키 값 없이).
- 처음 설정(`/api/setup`): 계정이 하나도 없을 때만, 출입 열쇠(SE2_ACCESS_KEY)를 지나온 요청이거나 바깥에 열지 않은 서버의 루프백 요청만 받는다(바깥에 열고 열쇠가 없으면 403 — 낯선 사람이 먼저 운영자 계정을 차지하지 못하게). 두 번째는 409. 키는 봉해 저장하고 응답 · 로그에 싣지 않는다(시험).
- 마스터 키: Secrets(`CREDENTIALS_KEY_V1`)가 먼저. 없으면 `online/start.mjs` 가 `data/online-master.key`(저장소 밖, 0600)를 만들어 쓴다 — 작업 공간 시험 운영용. DB 덤프만으로는 키를 열 수 없다는 성질은 그대로이고, 게시 전에는 Secrets 로 옮긴다(콘솔 안내).
- AI 키: 운영자가 `online/admin.mjs set-key` 로 표준 입력에서 받아 봉해 저장(명령줄 인자 · 콘솔 · DB · 생성 기록 · 작업 오류 문구 어디에도 원문 없음 — 시험). 화면으로는 받지 않는다(`auth.write` 403).
- 작업 손잡이(일시중지 · 이어 하기 · 치우기 · 답)도 프로젝트 소유 검사를 지난다 — 남의 jobId 로는 아무것도 못 한다(404).

| 학생 작품 열람 | **최상위 관리자만** 기관마다 켜고 끈다. 최상위 관리자 자신은 본문을 읽지 않는다(2026-10-05) | `org.settings adminCanReadProjects` 는 최상위 관리자가 아니면 403(시험) · 운영자 열람 길은 없다 |
| 수업 뒤 개인으로 이어 쓰기 | 결제가 정해지기 전에도 **열어 둔다** — 누구나 «내 AI 키»를 넣고(비용 주체 USER) 수업 작품을 **개인 작품으로 복사**한다. 원본은 기관에 남는다. 기관은 복사를 막을 수 있다(기본 허용). 키 칸에 «만 14세 이상만» 문구 — 실제 기준은 법률 확인 뒤(2026-10-05) | `me.key.set/list`(쓰기 전용 · 끝 네 자리) · `project.copy_personal`(제 작품만 · 기관 `allow_copy=false` 면 403 · 감사 로그) — 시험 |
| 자유 가입(나중) | 가입자는 **본인 API 키(BYOK, 비용 주체 USER)** 로 쓰고, **별도의 월간 프로그램 이용료**를 낸다. 결제 수단·방법은 미정 | 결제가 정해지기 전까지 **자유 가입은 막아 둔다** |

자유 가입을 열 때 갖출 것(설계만 — 결제가 정해지면 만든다):
- 가입 → 본인 credential 등록(서버에 봉인, 화면에 돌려주지 않음) → 이용료가 유효할 때만 **새 AI 작업** 등록(편집 · 열람 · 내보내기는 이용료와 무관하게 둘지 정책으로 정한다).
- 이용 상태(구독 유효/만료/정지)는 결제 연동이 정해 주는 값을 서버에 두고, 작업 등록 직전에 검사한다(기관 라이선스 검사와 같은 자리, 오류 code 는 `subscription_inactive`).
- AI 호출 비용은 가입자 키로 나가므로 플랫폼 비용이 아니다(USER) — 이용료와 섞어 기록하지 않는다(CLAUDE.md 원칙 7).
- 운영자가 만든 계정은 이 흐름을 거치지 않는다(어느 키 · 어떤 이용 조건으로 쓰는지는 운영자가 계정마다 정한다).

## 7. 사람이 결정해야 하는 정책 (미결)

아래는 코드가 대신 정할 수 없다(사용자 개입 규칙 — «개인정보·미성년자·보안·법률 정책»). 결정되면 이 표를 고친다.

| 항목 | 묻는 것 | 결정 전 기본(보수적) |
|---|---|---|
| 학생 개인정보 범위 | 이름/학교/연락처를 받는가 | login_id + 표시명만 |
| 보존 기간 | 수업·라이선스 종료 후 작품·로그·생성 입력 스냅샷을 얼마나 두는가 | 작품은 지우지 않음 · 프롬프트 원문 스냅샷은 저장하지 않음 |
| 미성년자 · 보호자 동의 | 몇 세 미만에 보호자 동의가 필요한가, 누가 받는가 | 파일럿 전 기관과 합의 |
| AI 입력 데이터 처리 | 학생 원고를 어느 provider 로 보내도 되는가, 무료 등급 금지 여부 | 기관이 고른 유료 credential 만 |
| 기관 관리자의 작품 열람 | 기본 허용인가 | 진행 상태만, 본문은 기관 정책으로 켬 |
| 포트폴리오(유튜브·제안서) 사용 | 동의 절차 | 별도 동의 없이는 사용하지 않음 |
| 자유 가입의 결제 | 결제 수단(카드 · 간편결제 · 계좌) · 대행사 · 환불 · 세금계산서 | 자유 가입 닫힘 |
| 운영자 발급 계정의 AI 비용 | 그 계정은 누구의 키로 도는가(본인 키 · 운영자 키) | AI 작업은 아직 닫혀 있음 — Sprint 9 에서 계정별 credential 로 |
| 영구 삭제 권한 | 학생/기관 관리자에게 주는가 | 휴지통까지, 영구 삭제는 플랫폼 관리자 |
