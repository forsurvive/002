# 보안 설계

> 상태: **초안 v1 (2026-10-04)**. §2 는 지금(개인판 + 1차 구현) 실제로 있는 것, §3 이후는 온라인판 설계.
> §7 의 항목은 **사람의 책임 있는 결정**이 필요하다 — 결정되기 전에는 그 기능을 production 에 열지 않는다.

## 1. 지킬 것(위협 모델 요약)

| 자산 | 위협 | 방어 |
|---|---|---|
| 작품(원고·자료·판) | 다른 사용자/기관이 읽기·고치기, 실수로 삭제, AI 실패로 덮어쓰기 | 서버측 권한 · 테넌트 격리(+RLS) · 논리 삭제 · AI 결과는 새 판으로만 |
| AI credential | 브라우저·로그·Git·오류 문구로 유출, 남의 키로 호출 | 서버측 암호화 저장 · worker 에서만 복호화 · 원문 재표시 금지 · 로그 가리기 |
| 비용 | 남의 credential 로 호출, 폭주(반복·루프) | credential 소유 해석 · 기관/전역 동시 상한 · 재시도 상한 · 관리자 지표 |
| 계정 | 비밀번호 추측, 세션 탈취, CSRF | scrypt · 로그인 속도 제한 · HttpOnly/Secure/SameSite 쿠키 · JSON 전용 + Origin 검사 |
| 학생 개인정보(미성년자 가능) | 과다 수집, 무기한 보존, 무단 공개 | 최소 수집(login_id + 표시명) · 보존 정책(§7) · 포트폴리오 사용 동의 별도 |

## 2. 지금 있는 것

### 2-1. 개인판(로컬) 문지기 — 기준선 그대로

- 바인딩 `127.0.0.1`. Host 는 `127.0.0.1`·`localhost` 만 → DNS 재바인딩 차단.
- `POST /api` 는 `Content-Type: application/json` 만(text/plain 단순 요청 CSRF 차단, `415`).
- `Origin` 이 있으면 `http://(127.0.0.1|localhost):<같은 포트>` 만(`403`). Origin 없는 요청(폰 중계기)은 통과.
- 인증 없음 — 그 PC 를 쓰는 사람이 주인. `data/auth.json` 의 API 키는 **평문**이며 화면에는 `hasKey` 만 내려간다(개인판 한계, README 가 USB 주의를 이른다).

### 2-2. 1차 구현(호스팅 실행)에서 더한 것 — `tools/hosting.mjs`

로컬 기본값에서는 **아무것도 바뀌지 않는다**. `SE2_HOST` 를 루프백이 아닌 주소(예: `0.0.0.0`)로 줄 때만 켜진다.

- **허용 호스트**: 루프백 이름 + `SE2_ALLOWED_HOSTS` + 플랫폼이 알려 준 도메인(`REPLIT_DOMAINS`, `REPLIT_DEV_DOMAIN`). 그 밖의 Host 는 `403`(재바인딩 방어 유지).
- **Origin**: 허용 호스트로 온 요청은 같은 이름에서 온 Origin 만(https 는 앞단 프록시가 포트를 바꿀 수 있어 이름만, http 는 포트까지).
- **스테이징 출입 열쇠**(`SE2_ACCESS_KEY`, HTTP Basic): 루프백이 아닌 주소에 열 때 **없으면 서버가 뜨지 않는다**(fail-closed).
  16자 미만이면 거절. 비교는 SHA-256 다이제스트의 `timingSafeEqual`. 사용자 이름은 무시.
  열쇠 없이 굳이 열려면 `SE2_ALLOW_OPEN=1` 을 **명시**해야 한다(권장하지 않음).
- 열쇠 없이 들어올 수 있는 것은 둘뿐이고 둘 다 원고를 담지 않는다: `GET /healthz`(«ok»), 그리고 플랫폼 상태 검사를 위한
  `GET /` 의 작은 안내 페이지(브라우저의 주소창 이동이면 곧바로 로그인 창을 띄운다).
- 이것은 **사람 계정이 아니다.** 스테이징에서 기능을 보는 동안 낯선 접근을 막는 임시 울타리이고, Phase 3 의 계정·세션이 대신한다.
  실제 학생/기관 데이터를 스테이징 1차 구성에 넣지 않는다.

## 3. 인증(Phase 3 설계)

- **앱 자체 계정**(Replit 등 호스팅 계정과 독립 — 명세 AH-9). `AuthProvider` 경계를 두어 필요하면 Clerk/OIDC 로 바꿀 수 있게.
- 비밀번호: `crypto.scrypt`(Node 내장, 표준 KDF — 새 암호를 만들지 않는다). 매개변수는 OWASP 권장치 이상, 솔트 16바이트, 문자열에 매개변수 함께 저장 → 나중에 올릴 수 있다.
- 세션: 32바이트 난수 토큰을 쿠키(`HttpOnly; Secure; SameSite=Lax; Path=/`)에, DB 에는 **SHA-256 해시만**. 만료(예: 14일)·유휴 만료·로그아웃·비밀번호 변경 시 전부 폐기.
- 학생: 초대 코드(만들 때 한 번 보여 주고 해시만 저장, 만료·사용 횟수) → login_id + 비밀번호 설정. 이메일 강제 없음(명세 §34).
- 로그인 실패: 같은 문구(계정 존재 여부를 흘리지 않음) · IP+계정 기준 속도 제한 · 감사 로그.

## 5. Credential 저장

- **봉투 암호화**: AES-256-GCM, 행마다 12바이트 nonce, 인증 태그 저장. AAD = `owner_type|owner_id|provider|credential_id`(행 바꿔치기 방지).
- 마스터 키: 플랫폼 Secrets 의 `CREDENTIALS_KEY_V1`(32바이트, base64). 행에 `key_version` → 새 키로 다시 암호화(rotate) 가능.
- 복호화는 **worker 의 호출 직전**에만, 결과 문자열은 그 호출의 지역 변수로만. 웹 서버는 «저장·폐기·연결 테스트 요청»만 한다.
- 화면·API 응답: `{ provider, status, keyHint:'…a1b2', lastVerifiedAt }`. 원문은 다시 내려가지 않는다(명세 §16).
- 로그·오류·감사 로그에 키·`Authorization` 헤더·credential 객체 전체를 남기지 않는다 — 로거에 가리기 규칙(키 모양 정규식 + 이름 기반) + 시험.
- 플랫폼 공용 키(향후 managed AI)는 Secrets 의 환경 변수, 기관/개인 키는 **DB 에 암호화**(명세 AH-7 — 공용 환경 변수에 넣지 않는다).

## 6. 웹 보안 기본값(온라인)

- HTTPS 전용(플랫폼 TLS) · `Secure` 쿠키 · HSTS(사용자 도메인 연결 뒤).
- CSRF: `SameSite=Lax` + 상태 변경은 `POST /api`(JSON 전용) + Origin/Referer 검사(지금 문지기 확장).
- 헤더: `X-Content-Type-Options: nosniff` · `Referrer-Policy: same-origin` · CSP(인라인 스크립트 없음 — 지금 화면은 외부 파일만 쓴다) ·
  `frame-ancestors` 는 운영 도메인에서만 켠다(Replit 작업 공간 미리보기가 iframe 이므로 스테이징에서는 끔).
- 요청 본문 상한(예: 2MB, 자료 붙여 넣기는 파일 업로드 경로로) · 업로드 형식/크기 검사(txt·md 먼저, 명세 §63).
- 속도 제한: 로그인·초대 수락·작업 등록에 IP/계정 기준.
- 오류 응답에 내부 정보(스택·SQL·provider 원문) 금지. 다른 테넌트 id 는 «없음(404)».
- 감사 로그(명세 §61): 로그인/실패 · 권한 변경 · 기관 생성 · 라이선스 변경 · credential 변경 · 프로젝트 삭제 · 중요한 작품 삭제/복구.

## 7. 사람이 결정해야 하는 정책 (미결)

아래는 코드가 대신 정할 수 없다(사용자 개입 규칙 — «개인정보·미성년자·보안·법률 정책»). 결정되면 이 표를 고친다.

| 항목 | 묻는 것 | 결정 전 기본(보수적) |
|---|---|---|
| 학생 개인정보 범위 | 이름/학교/연락처를 받는가 | login_id + 표시명만 |
| 보존 기간 | 수업·라이선스 종료 후 작품·로그·생성 입력 스냅샷을 얼마나 두는가 | 작품은 지우지 않음 · 프롬프트 원문 스냅샷은 저장하지 않음 |
| 미성년자 · 보호자 동의 | 몇 세 미만에 보호자 동의가 필요한가, 누가 받는가 | 파일럿 전 기관과 합의 |
| AI 입력 데이터 처리 | 학생 원고를 어느 provider 로 보내도 되는가, 무료 등급 금지 여부 | 기관이 고른 유료 credential 만 |
| 기관 관리자의 작품 열람 | 기본 허용인가 | 진행 상태만, 본문은 기관 정책으로 켬 |
| 포트폴리오(유튜브·제안서) 사용 | 동의 절차 | 별도 동의 없이는 사용하지 않음 |
| 영구 삭제 권한 | 학생/기관 관리자에게 주는가 | 휴지통까지, 영구 삭제는 플랫폼 관리자 |
