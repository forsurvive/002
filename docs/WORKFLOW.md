# 단계형 작업 흐름 · 미니 강의 카드 — 설계 초안

> 상태: **검토 대기 (2026-10-04)** — 사용자 확인 전에는 만들지 않는다. 결정할 것은 §7.
> 원칙: 지금의 자유 문서 작업(원소)을 바꾸지 않고 **그 위에 데이터로 얹는다**. 자동으로 끝까지 써 내려가는 파이프라인이 아니다(CLAUDE.md 원칙 8).

## 1. 무엇을 만드나 — 한 줄

작품 하나를 «공식 스토리 workflow» 16단계로 나누어, 단계마다 **생성 → 검토 → 수정 → 승인 → 다음 단계**로 사람이 한 걸음씩 진행한다.
각 단계의 결과는 **보통 문서**(판 · 참조 · 확정본 · 합평 · 모순 검사가 그대로 되는 그 문서)이고, 단계는 그 문서에 «이 단계의 산출물»이라는 표를 달 뿐이다.

## 2. 단계 목록 (기본 템플릿 `story_creation`)

| # | 단계 | 결과 문서 | 앞 단계에서 자동 추천하는 참조 |
|---|---|---|---|
| 1 | 작품 규격 · 자료 입력 | (프로젝트 만들기 창 — 이미 있음) | — |
| 2 | 자료 분석 | «자료 분석» (이미 자동으로 생김) | 자료 전부 |
| 3 | 세계관 | «세계관» | 자료 분석 |
| 4 | 서사 재료 선별 · 정리 | «서사 재료» | 자료 분석 · 세계관 |
| 5 | 작품 기획서 | «기획서» | 세계관 · 서사 재료 |
| 6 | 기획서 수정 | «기획서»의 새 판 (같은 문서) | 기획서 |
| 7 | 기획서에 맞춘 세계관 수정 | «세계관»의 새 판 | 기획서 · 세계관 |
| 8 | 인물 설계(캐릭터 풀) | «인물 풀» | 기획서 · 세계관 |
| 9 | 주요 인물 선정 | «주요 인물» | 인물 풀 · 기획서 |
| 10 | 대략적인 플롯 + 인물별 아크 | «대략 플롯» | 기획서 · 주요 인물 · 세계관 |
| 11 | 상세 플롯 | «상세 플롯» | 대략 플롯 · 주요 인물 |
| 12 | 상세 플롯 수정 | «상세 플롯»의 새 판 | 상세 플롯 |
| 13 | 회차 / 파트 구체화 | «회차 계획» | 상세 플롯 · 기획서(분량) |
| 14 | 장면 구체화 | 회차마다 «N화 장면» | 회차 계획 · 상세 플롯 |
| 15 | 본문 작성 | 회차마다 «N화» | N화 장면 · 주요 인물 · 세계관 |
| 16 | 완성 | (점검 — 모순 검사 · 합평을 권하고 내보내기) | 본문 전부 |

- 수정 단계(6 · 7 · 12)는 새 문서를 만들지 않고 **그 문서의 새 판**을 쌓는다(앞 판은 이력에 그대로).
- 15 본문 단계는 **끌 수 있다**(기획서 «본문 집필 단계는 제외할 수 있도록» — 프로젝트 설정의 토글).
- 단계는 새 «작법 프롬프트»가 아니다. 지금의 갱신(`F-UPDATE`)에 «이번 단계에 할 일» 한 문단과 추천 참조만 얹는다(DESIGN «작법은 문서다»를 지킨다).

## 3. 화면 — 어떤 모습인가

### 3-1. 작업실 왼쪽에 «단계» 탭

```
┌───────────────┬──────────────────────────────────────────────────────┐
│ 스토리 엔진    │  ‹  바닷가 마을 이야기                                │
│ 작업실         │                                                      │
│ ▶ 단계         │  단계                                     본문 단계 ◉ │
│ 설정           │  ─────────────────────────────────────────────────── │
│               │  ● 1 작품 규격 · 자료        완료                     │
│               │  ● 2 자료 분석               승인됨                   │
│               │  ◐ 3 세계관                  초안 — 검토하세요   [열기] │
│               │  ○ 4 서사 재료 선별 · 정리    시작 전          [시작] │
│               │  ○ 5 작품 기획서              시작 전                 │
│               │  …                                                   │
│ 작업           │  ○ 15 본문 작성 (꺼짐)                               │
│  세계관 · 1분  │  ○ 16 완성                                           │
└───────────────┴──────────────────────────────────────────────────────┘
  ○ 시작 전   ◐ 초안(검토 · 수정 중)   ● 승인됨   ⚠ 앞 단계가 바뀜   ⤼ 건너뜀
```

- **강제 순서가 아니다.** 어느 단계든 누를 수 있다. 앞 단계가 승인 전이면 «앞 단계가 아직 승인 전입니다»라고 알리기만 한다.
- 지금의 «작업실»(카테고리 · 문서 목록)은 그대로 있다. 단계 결과 문서도 작업실의 «단계» 카테고리에 보통 문서로 보인다.

### 3-2. 단계를 누르면 — 단계 창

```
┌ 3 세계관 ─────────────────────────────────────────────────── × ┐
│ 이 단계에서 만드는 것                                           │
│   이야기가 벌어지는 세계의 규칙 · 장소 · 사회 · 역사를 정리한다.     │
│                                                               │
│ 참조 (앞 단계에서 추천 — 확인하고 빼거나 더할 수 있다)              │
│   ☑ 자료 분석   ☑ 자료: 설정 노트   ☐ 작법서: …     [+ 더하기]     │
│                                                               │
│ 이번 요청사항 (이번 한 번만 — 저장되지 않는다)                     │
│   ┌──────────────────────────────────────────────────────────┐ │
│   │ 마법은 없고, 바다 무역이 중심인 세계로                      │ │
│   └──────────────────────────────────────────────────────────┘ │
│ 이 문서의 요청사항 (계속 적용 — 문서에 남는다)   [문서에서 고치기] │
│                                                               │
│                 [ 생성 ]                                       │
└───────────────────────────────────────────────────────────────┘
```

- [생성] → 지금과 같은 작업(job)이 돈다(왼쪽 작업 줄 · 일시중지 · 삭제 그대로). 결과는 «세계관» 문서의 새 판.
- «이번 요청사항»(일회성)과 «문서 요청사항»(지속)을 나눈다(CLAUDE.md «사용자 개입 규칙»). 일회성은 생성 기록(generation_runs)에만 남는다.

### 3-3. 결과가 오면 — 검토 · 수정 · 승인

```
┌ 3 세계관 — 초안 ───────────────────────────────────────────── × ┐
│ [문서 열기]  본문 · 이력 · 참조 · 확정본 — 지금의 문서 창 그대로     │
│                                                                │
│ 할 수 있는 것                                                    │
│   [다시 생성]  새 판으로 다시 (요청사항을 바꿔서)                    │
│   [직접 고치기] 문서 창에서 본문을 고친다                            │
│   [합평 받기] [모순 검사]  지금 기능 그대로                         │
│                                                                │
│   [ 승인하고 다음 단계로 ]   ☐ 이 문서를 확정본으로도 켜기            │
└────────────────────────────────────────────────────────────────┘
```

- **승인 ≠ 확정본.** 승인은 «이 단계의 산출물로 인정», 확정본은 «참조에서 최우선 사실». 승인할 때 확정본 켜기는 **체크박스로 제안만** 하고 기본은 꺼짐.
- 승인한 뒤에도 다시 열어 고칠 수 있다(새 판이 쌓일 뿐). 승인된 단계의 문서가 바뀌면 그 뒤 단계들에 **⚠ 앞 단계가 바뀜** 표만 단다 — **자동으로 다시 만들지 않는다**.

## 4. 미니 강의 카드 — AI 가 쓰는 동안 보이는 짧은 설명

### 4-1. 학생 화면 — 생성이 도는 동안

```
┌ 세계관을 만드는 중 · 1분 20초 ─────────────────────────────────┐
│ 📘 세계관이란                                                    │
│   인물이 «당연하게» 여기는 것들의 목록이다. 독자가 처음 보는          │
│   규칙은 사건 속에서 드러나야 설명처럼 느껴지지 않는다.               │
│                                                                 │
│ 결과를 읽을 때 볼 점                                               │
│   · 이 세계에만 있는 규칙이 이야기의 갈등을 만들어 내는가?            │
│   · 규칙끼리 서로 어긋나지 않는가?                                 │
│                                                                 │
│ 생각해 볼 질문                                                     │
│   이 세계에서 주인공이 가장 잃기 싫은 것은 무엇일까?                  │
└─────────────────────────────────────────────────────────────────┘
```

- 카드 = **무엇인가(2~3문장) · 볼 점(2~3개) · 질문(1개)**, 단계마다 하나, 300자 안팎. 화면 오른쪽 아래에 작은 카드로(작업을 가리지 않게), 닫을 수 있다.
- 결과가 오면 카드가 **«방금 배운 기준으로 읽기»** 체크리스트로 바뀐다(볼 점에 스스로 체크 — 점수가 아니다, 저장하지 않는다).
- 학생 화면에는 **비용 · 횟수 · 모델 이름이 없다**(지금 원칙 그대로).

### 4-2. 강사 화면 — «지금 강의 포인트»

- 관리/수업 현황 표에 학생마다 **지금 단계 · 상태**(시작 전 / 생성 중 / 초안 / 승인)가 보인다.
- 단계를 누르면 강사용 메모(`teaching_note` — 그 단계에서 학생들이 자주 막히는 곳 · 짚어 줄 말, 500자 안팎)가 보인다.
- 강사는 수업마다 카드 문구를 **고쳐 쓸 수 있다**(기본 문구 위에 덮어쓰기 — 원문은 남는다).

### 4-3. 켜고 끄기

| 어디서 | 기본 |
|---|---|
| 기관 설정 «학생에게 강의 카드 보이기» | 켜짐 |
| 개인판 · 온라인 개인 사용자 «작업 중 설명 보기» | **꺼짐**(작가에게는 방해일 수 있다) |

### 4-4. 카드 문구는 누가 쓰나

16단계 × (학생 카드 + 강사 메모)의 **초안을 제가 써서** `config/workflows/story_creation.json` 에 둔다 → **사용자가 검토 · 수정** → 확정.
특정 작법 이론을 «정답»으로 박지 않는다 — «볼 점»은 질문 꼴로 쓴다.

## 5. 데이터 — 어떻게 들어가나

- **단계 정의는 설정 파일**(`config/workflows/story_creation.json`): `{ key, title, order, output: 'document'|'revision'|'perEpisode', task, inputs[], optional, studentCard{what, look[], ask}, teachingNote }`. 코드에 박지 않는다 — 문구를 고쳐도 코드를 고치지 않는다.
- **단계 상태는 프로젝트 덩어리에** `p.stages = { [key]: { status, docId, approvedAt, approvedVersion, skipped } }` — 개인판(JSON)과 온라인판(표의 jsonb 칸)이 같은 Core 함수(`core/workflow/`)로 고친다.
- 문서에는 `stageKey` 한 칸(이 문서가 어느 단계의 산출물인가).
- 생성은 지금의 `update` 작업 그대로 + `taskExtra`(단계의 할 일) · 일회성 요청 · 고른 참조. 생성 기록에 `workflow_stage` 를 남긴다.
- 강사 화면의 «지금 단계»는 `p.stages` 에서 읽는다(수업 현황 문에 칸 하나).

## 6. 만드는 순서 (승인 뒤)

1. Core: 단계 정의 읽기 · 단계 상태 전이(시작 → 초안 → 승인 · 건너뜀 · 앞 단계 바뀜 표) · 추천 참조 계산 — 순수 함수 + 시험.
2. 생성 연결: 단계 → 문서 만들기/새 판 → `update` 작업(일회성 요청 · 참조) — 개인판 · 온라인 둘 다 + 시험.
3. 화면: «단계» 탭 · 단계 창 · 승인(확정본 제안 체크).
4. 강의 카드: 학생 카드 · 결과 뒤 체크리스트 · 기관/개인 켜고 끄기 · 강사 메모 · 수업 현황의 «지금 단계».
5. 카드 문구 초안 → 사용자 검토.
